## 1. 平台硬规则（红线）

| 项目 | 规则 |
|---|---|
| 标题 | ≤ 20 字，必须含搜索关键词（用户会搜的词，如"鸿蒙""互传""换机"） |
| 正文 | ≤ 1000 字 |
| 图集 | ≤ 18 张，建议 3:4 竖图，第一张为封面 |
| 外链 | 🚫 正文禁止任何站外链接（GitHub、官网等），会被限流 |
| 二维码 | 🚫 微信/公众号/小程序等站外二维码禁止出现在图片中；App 内截图自带的二维码建议打码，机审对二维码敏感 |
| 导流词 | 🚫 禁止"加微信""公众号""扫码进群"等导流表述 |
| 获取方式 | 站外资源统一改为「评论区置顶话术」引导（扣 1 私信 / 应用市场搜索） |

## 2. 文案风格

- **开头**：痛点场景三连（"给同事传文件，微信提示超过1GB……"），3 行内钩住
- **结构**：一句话引出产品 → 卖点清单（🔹/✅ 分点，每点一行一个卖点）→ 适用场景（▫️）→ 费用/获取方式 → 互动提问收尾
- **语气**：口语化、第一人称、像朋友安利；删光"据悉""旨在"等公文体
- **emoji**：每段 1~2 个当项目符号用，不堆砌
- **标签**：8~10 个，混合大词（#实用app安利 #效率工具）+ 精准词（#鸿蒙 #文件传输）
- **评论区置顶**：下载/获取引导放自己评论里置顶，不放正文

## 3. 图片处理

extract_article.py 提取图片后，逐张阅读并分类：

- **截图**（App 界面、产品图）→ 重命名为 `序号_内容.jpg` 保留，作图集
- **装饰图**（分隔线、花纹、纯背景）→ 删除
- **站外二维码**（微信群、公众号、小程序码）→ 移入 `不使用_站外二维码/` 隔离
- **含二维码的产品截图** → 保留但文件名加 `_含二维码` 后缀，文案中提醒用户打码

若 cv2 可用，先读 `qr_scan.txt` 辅助判断；无论脚本结果如何，都要亲眼过一遍图片（脚本只检测可解码的二维码，小程序码、装饰性码可能漏检）。

## 4. 输出文件模板

在 XHS 目录输出 `小红书图集文案.md`，固定六节：

```markdown
# <产品名> · 小红书图集笔记

## 一、标题（选 1 个，≤20 字）
1. **首选标题**（推荐理由）
2~4. 备选

## 二、图集顺序与图注
| 序号 | 图片 | 图注 |
（标注哪张作封面、哪张含二维码需打码）

## 三、正文（直接复制，约 XXX 字）
<按第 2 节风格写好的完整正文，末尾带标签>

## 四、评论区置顶话术
<获取方式引导，不能含链接>

## 五、发布前 Checklist
- [ ] 标题 ≤20 字含搜索关键词
- [ ] 含二维码的图已打码
- [ ] 无外链、无站外二维码、无导流词
- [ ] 正文 ≤1000 字
- [ ] 发布后置顶下载引导评论

## 六、后续第二波（可选）
<若内容适合视频演示，给一条视频笔记思路>
```
